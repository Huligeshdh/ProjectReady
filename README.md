# 🚀 ProjectReady

### AI-Powered Final-Year Project Mentor

> **From project idea to implementation — ProjectReady helps students plan, build, review, and improve their final-year projects with AI.**

ProjectReady is an AI-powered platform designed for final-year students who have an idea but don't know how to turn it into a practical, technically strong, and well-structured project.

It provides guidance throughout the complete project lifecycle:

```text
Idea
 ↓
Feasibility
 ↓
Research
 ↓
Blueprint
 ↓
Roadmap
 ↓
Development
 ↓
AI Mentoring
 ↓
Code Submission
 ↓
AI Code Evaluation
 ↓
Improvements
 ↓
Project Ready
```

---

## What is ProjectReady?

ProjectReady is more than an AI chatbot.

It combines:

- AI project ideation
- Feasibility analysis
- Project architecture
- Research discovery
- Development planning
- Project-aware AI mentoring
- Full ZIP codebase analysis
- Security analysis
- Testing analysis
- Accessibility analysis
- Efficiency analysis
- Problem-statement alignment
- Project health evaluation
- Improvement recommendations

The objective is simple:

**Help students build better projects — not just generate project ideas.**

## ✨ Core Features

### 1. 💡 AI Project Idea Generator

Generate personalized final-year project ideas based on:

- Skills
- Interests
- Academic background
- Domain
- Team size
- Available time
- Budget
- Hardware/GPU availability
- Preferred technologies

Each idea can be evaluated based on:

- Skill Match
- Feasibility
- Innovation
- Time Fit
- Technical Complexity
- Practical Value

ProjectReady can also help narrow an over-scoped idea into a realistic MVP.

---

### 2. 📊 Feasibility Analyzer

Before starting development, ProjectReady evaluates whether the proposed project is realistic.

It considers factors such as:

- Technical feasibility
- Dataset availability
- Required technologies
- Development time
- Hardware requirements
- Budget
- Team size
- Deployment requirements
- Project complexity

The goal is to prevent students from starting projects that look impressive but cannot realistically be completed.

---

### 3. 🏗️ Project Blueprint

Once an idea is selected, ProjectReady helps convert it into a technical blueprint.

The blueprint can include:

- System architecture
- Major modules
- Features
- Technology stack
- Database design
- API requirements
- AI/ML components
- Frontend/backend structure
- Development considerations

---

### 4. 📚 Research Hub

ProjectReady helps students discover resources related to their project.

**Research Papers**

Find related academic papers using sources such as:

- Crossref
- OpenAlex
- arXiv

**GitHub Repositories**

Discover relevant open-source repositories for:

- Understanding implementations
- Learning architecture
- Finding inspiration
- Comparing approaches

**Learning Videos**

Find relevant educational videos and tutorials.

**Datasets**

Discover datasets relevant to the selected project domain.

The Research Hub is designed to help students move from "I have an idea" to "I have references and resources to actually build it."

### 🏆 8. AI Code Submission Evaluation

ProjectReady evaluates the submitted code using six major criteria:

| Criterion | What is evaluated |
|---|---|
| 🧹 Code Quality | Readability, structure, maintainability, complexity |
| 🔐 Security | Secrets, vulnerabilities, unsafe practices |
| ⚡ Efficiency | Algorithms, queries, memory and unnecessary processing |
| 🧪 Testing | Tests, edge cases, validation and coverage where measurable |
| ♿ Accessibility | Labels, keyboard navigation, semantic HTML and accessibility |
| 🎯 Problem Alignment | Whether the implementation actually solves the stated problem |

The result is an:

**AI Code Submission Score**

Example:

```text
AI CODE SUBMISSION

84 / 100

Code Quality          88
Security              79
Efficiency            84
Testing               67
Accessibility         91
Problem Alignment     86
```

> **Important:** This is an AI-generated readiness score based on the evaluation criteria. It is not claimed to be the official competition score.

### 🎯 9. Problem Statement Alignment

This is one of the most important ProjectReady features.

ProjectReady compares:

```text
What you planned
        ↓
What you promised
        ↓
What you actually implemented
```

Example:

| Planned Feature | Detected Implementation | Status |
|---|---|---|
| AI Recommendation | Detected | ✅ |
| Authentication | Detected | ✅ |
| Research Module | Partial | ⚠️ |
| Analytics | Not detected | ❌ |

The system can identify gaps between the original project plan and the submitted implementation.

This answers a critical question:

> **"Did I actually build what I said I would build?"**

### 🩺 10. Project Health Evaluation

ProjectReady provides a broader project health assessment.

It can consider:

- Technical quality
- Feasibility
- Innovation
- Research quality
- Implementation quality
- Security
- Testing
- Accessibility
- Problem alignment
- Project risks

The result is a broader:

**Project Survival Score**

This is different from the AI Code Submission Score.

- **AI Code Submission Score** — Focuses on the submitted code and six evaluation criteria.
- **Project Survival Score** — Provides a broader view of the project's overall readiness.

## 🧠 Multi-Provider AI Architecture

ProjectReady is designed with an AI provider abstraction layer.

Supported providers include:

- Google Gemini
- OpenAI
- NVIDIA
- Ollama

The architecture allows different AI providers to be used for different tasks.

Example:

```text
                 ┌───────────────┐
                 │   AI Router   │
                 └───────┬───────┘
                         │
        ┌────────────────┼────────────────┐
        ↓                ↓                ↓
     Gemini           OpenAI           NVIDIA
        │                │                │
        └────────────────┼────────────────┘
                         ↓
                      Ollama
                    (Local AI)
```

A fallback mechanism can be used when a configured provider is unavailable.

Ollama can also be used for local/private AI workloads.

## 🚀 Getting Started

### Prerequisites

Make sure you have installed:

- Python 3.11+
- Node.js 18+
- npm
- Git

Optional:

- Ollama
- NVIDIA GPU / CUDA for supported local workloads

### 1. Clone the Repository

```bash
git clone https://github.com/Huligeshdh/ProjectReady.git
cd ProjectReady
```

### 2. Backend Setup

Navigate to the backend:

```bash
cd backend
```

Create a virtual environment.

**Windows**

```bash
python -m venv venv
venv\Scripts\activate
```

**Linux/macOS**

```bash
python3 -m venv venv
source venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

### 3. Environment Variables

Create a `.env` file:

```env
GEMINI_API_KEY=your_gemini_api_key
OPENAI_API_KEY=your_openai_api_key
NVIDIA_API_KEY=your_nvidia_api_key

OLLAMA_BASE_URL=http://localhost:11434

DATABASE_URL=sqlite:///./projectready.db
```

Only configure the providers you intend to use.

#### Security

> ⚠️ **Never commit `.env` to GitHub.**

Make sure `.env` is included in `.gitignore`.

Use `.env.example` for documenting required variables.

### 4. Start the Backend

From the backend directory:

```bash
python start_backend.py
```

Or use the project's configured FastAPI/Uvicorn command.

The API should become available at the configured backend URL.

### 5. Frontend Setup

Open another terminal:

```bash
cd frontend
npm install
npm run dev
```

Open the URL displayed by Vite in your browser.

## 🛡️ Security Considerations

ProjectReady takes uploaded source code seriously.

ZIP analysis should use safe processing practices such as:

- Isolated extraction
- Path traversal protection
- File validation
- File-size limits
- Secret masking
- Restricted execution
- Authentication
- User-scoped project access

Submitted project code should not be executed directly on the main backend.

If runtime testing is implemented, it should occur in an isolated environment with appropriate:

- CPU limits
- Memory limits
- Execution timeout
- Filesystem isolation
- Network restrictions
